<objective>
Execute write operations (git, GitHub, Jira) with bot attribution, approval gate,
and post-hoc audit logging. Run commands directly in the terminal — no intermediary CLI tool.
</objective>

<config>

## Attribution Config

Bot identity for commits and footers (from ~/.carter/config.toml):

- bot_name: `{{BOT_NAME}}`
- bot_email: `{{BOT_EMAIL}}`
- signing_key: `{{SIGNING_KEY}}`
- footer: `This comment was generated by {{BOT_NAME}}.`

If you need to verify these values, run: `carter-ops config --emit`

</config>

<workflow>

## Required Workflow

1. **ASSESS** — Run read commands to understand current state (`git status`, `git diff`, `git log --oneline -5`, etc.)
2. **PLAN** — Show the user a structured plan with the exact commands you will run, including attribution flags
3. **APPROVE** — Wait for user confirmation before executing any write command
4. **EXECUTE** — Run commands in terminal with attribution flags
5. **AUDIT** — Run: `carter-ops audit --operation <name> --params '<json>' --result <success|failure> --identifiers '<json>'`
6. **REPORT** — Tell the user what happened (branch name, commit SHA, PR URL, etc.)

**NEVER execute write commands without showing the plan and getting approval first.**

</workflow>

<git-operations>

## Git Operations

### Create branch

```bash
git checkout <base> && git pull origin <base> && git checkout -b <branch-name>
```

### Stage and commit

```bash
git add <file1> <file2> ...
git commit --author='{{BOT_NAME}} <{{BOT_EMAIL}}>' -S -m "<message>"
```

### Push

```bash
git push -u origin <branch-name>
```

### Complete flow (branch + commit + push)

```bash
git checkout <base> && git pull origin <base> && git checkout -b <branch-name>
git add <file1> <file2> ...
git commit --author='{{BOT_NAME}} <{{BOT_EMAIL}}>' -S -m "<message>"
git push -u origin <branch-name>
```

### Commit message conventions

- Conventional format: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`
- Present tense: "add feature" not "added feature"
- Reference issues: `Closes #70` or ticket ID in body

</git-operations>

<github-operations>

## GitHub Operations (via gh CLI)

Append this footer to ALL `--body` values:

```
\n\n---\n_This was generated by {{BOT_NAME}}._
```

### Commands

```bash
# Create issue
gh issue create --repo <owner/repo> --title "<title>" --body "<body>" [--label "<labels>"]

# Comment on issue
gh issue comment <number> --repo <owner/repo> --body "<body>"

# Create PR
gh pr create --repo <owner/repo> --title "<title>" --head <branch> --base <base> --body "<body>" [--draft]

# Comment on PR
gh pr comment <number> --repo <owner/repo> --body "<body>"
```

</github-operations>

<jira-operations>

## Jira Operations (via curl to REST API v2)

Requires env vars: `ATLASSIAN_URL`, `ATLASSIAN_EMAIL`, `ATLASSIAN_API_TOKEN`

Append this footer to ALL body text: `\n\n_This comment was generated by {{BOT_NAME}}._`

Use REST API **v2** (wiki markup in body field), NOT v3 (ADF JSON).

### Comment on ticket

```bash
curl -s -X POST \
  -u "${ATLASSIAN_EMAIL}:${ATLASSIAN_API_TOKEN}" \
  -H "Content-Type: application/json" \
  "${ATLASSIAN_URL}/rest/api/2/issue/<TICKET>/comment" \
  -d '{"body": "<wiki-markup-body>"}'
```

### Create issue

```bash
curl -s -X POST \
  -u "${ATLASSIAN_EMAIL}:${ATLASSIAN_API_TOKEN}" \
  -H "Content-Type: application/json" \
  "${ATLASSIAN_URL}/rest/api/2/issue" \
  -d '{"fields":{"project":{"key":"<KEY>"},"issuetype":{"name":"<TYPE>"},"summary":"<SUMMARY>","description":"<DESC>"}}'
```

### Transition ticket

```bash
# First get available transitions:
curl -s -u "${ATLASSIAN_EMAIL}:${ATLASSIAN_API_TOKEN}" \
  "${ATLASSIAN_URL}/rest/api/2/issue/<TICKET>/transitions"

# Then apply:
curl -s -X POST \
  -u "${ATLASSIAN_EMAIL}:${ATLASSIAN_API_TOKEN}" \
  -H "Content-Type: application/json" \
  "${ATLASSIAN_URL}/rest/api/2/issue/<TICKET>/transitions" \
  -d '{"transition":{"id":"<ID>"}}'
```

</jira-operations>

<error-recovery>

## Error Recovery

| Error | Recovery |
|-------|----------|
| Push rejected (non-fast-forward) | `git pull origin <branch> --rebase` then retry push |
| Branch already exists | Ask user: switch to existing branch or pick a new name? |
| Signing fails (`-S` error) | Ask user: proceed without signing? |
| Jira 403 | Check env vars: `echo $ATLASSIAN_URL $ATLASSIAN_EMAIL` — report which are empty |
| `gh` not found | Suggest `brew install gh` or fall back to `curl` with `$GITHUB_TOKEN` |
| Git author flag rejected | Verify config: `carter-ops config --emit` |

</error-recovery>

<boundaries>

## What is NOT ops:

Read operations run directly without the `ops:` prefix — no approval needed:

`git log`, `git status`, `git diff`, `git blame`, `git branch --list`,
`gh issue list`, `gh pr list`, `gh pr view`, JQL queries via MCP.

</boundaries>
